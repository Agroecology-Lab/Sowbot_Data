What the stack does

The aim of #116 is to get logic out of NiceGuiNode (ui_node.py) into layers. On caatinga-dev it was 4,195 lines. On ui-116-run-plan-sim-system (head caa70b9) it is 1,589.

PR

Change

#152 Alan services

Drive, robot brain, row discovery and navigation as domain services, application services and view models

#153 Telemetry

Odometry and GPS state moves into TelemetryDomainService, TelemetryApplicationService and TelemetryViewModel

#156 Topo rows

Row geometry, contour planning, row building and repair become pure modules (row_planning, topo_row_builder, plan_import), with regression tests

#158 RosGateway

Subscriptions, timers and tool publishers go through RosGateway. The mission executor moves into MissionDomainService, and ObstacleManager and MissionStore use the gateway too

#161 Obstacles

ObstacleViewModel, and the obstacle cards move to pages/obstacle_cards.py. Saved missions sit behind MissionViewModel

#162 Topology edits

TopologyEditService holds the rules for dropping a node, saving F2C rows, repairing and deleting. The node methods become thin wrappers

#163 Sim assets

SimAssetService handles crop-model upload validation and writing, plus the soil zip import

Branch ui-116-run-plan-sim-system (PR number to add)

UI split into Run, Plan, Sim and System tabs. SimPage and SystemPage are classes with their cards under pages/sim/ and pages/system/. SimWorldService rebuilds the Gazebo world. Tool processes move into process_registry. Map archive goes behind TopologyViewModel. Layer rules are enforced with import-linter in CI (six contracts). 57 test files

#155 (optical flow in Docker) and #157 (vendored skills) are unrelated to the refactor.

The three items listed as outstanding in the 9 October comment are done: the subscription, timer and tool publishers go through RosGateway, the mission executor is in MissionDomainService, and the F2C-to-topo glue is in TopologyEditService.stage_f2c_save.

The Run and Plan tabs are still methods on NiceGuiNode, which is why they are drawn as red dashed boxes. The Sim and System tabs are page classes. Because the Plan tab lives on the node, it reaches TopologyEditService, row_planning, devkit_f2c_planner and MissionDomainService directly instead of going through a ViewModel.

Decision: drop “Facade” as a layer name

Nothing built plays that role. Its real job, a UI-neutral boundary that REST, MQTT and LoRa adapters can share, belongs to the application services. The ViewModels can’t take it on, because they are NiceGUI-specific.

Names

Layer

Name

Rule

UI

Page

Layout only. Imports ViewModels only (enforced by import-linter). Tool processes are the one exception: cards start them through process_registry, and Medkit still uses subprocess in tools_card

UI state

ViewModel

UI state and user intents. It is the NiceGUI adapter, and the only place presentation formatting happens

Boundary

Application service

The “Robot API”. Use cases, plain dataclasses in and out, no UI or rclpy types. Phase 2 adapters call this layer

Live state

Domain service

Holds live state (TopoDoc, mission state). Talks to ROS only through RosGateway

Persistence

Store

TopoMapStore, MissionStore. Owned by application services. TopoMapStore sits in the domain_services package for now

Algorithms

Pure module

row_planning, topo_row_builder, plan_import. No state, no ROS. F2C is the separate devkit_f2c_planner package

ROS

RosGateway

Creates publishers, subscriptions, clients and timers. Five modules still import rclpy.qos directly (see below)

Processes

process_registry

Registry of long-running tool processes (RViz, Gazebo, explorer, grapher, neo), shared by every browser session. No NiceGUI or ROS imports

Phase 2 edge

Adapter

RestAdapter, MqttAdapter, ReticulumAdapter. Each is thin and calls application services. Not built

Phase 2 central

Fleet Gateway

Renamed from “Central Gateway” so “gateway” means one thing only. Not built

Dependency rule: Page → ViewModel → Application service → Domain service / Store / Pure module → RosGateway. Nothing points upward or skips a layer.

import-linter enforces this in CI (make lint-imports, .importlinter) with six contracts:

  1. Pages import only ViewModels.

  2. Pages do not spawn processes.

  3. ViewModels do not reach domain services, stores or ROS.

  4. Services are UI-neutral.

  5. Domain services do not import application services.

  6. Only RosGateway touches rclpy.

Each exception is listed in .importlinter with a TODO(#116) and the check fails if one becomes stale.

How the old Facade duties are split

  • ROS message to plain type: RosGateway and the domain services.

  • Plain type to display format: ViewModel.

  • Plain type to wire format (JSON, protobuf, Reticulum frames): Adapter (Phase 2, not built).

Consequences

  • The persistence objection no longer applies. achurichi’s rule was “no state or persistence in the Facade”. That was about a layer that doesn’t exist now. Stores sit in the application layer, as the build already has them.

  • Application services must stay thin orchestration. Planning lives in pure modules and the executor in MissionDomainService. Otherwise the monolith concern comes straight back.

  • MissionStore no longer bypasses the layers. In the 15 August diagram MissionRunner and MissionStore bypassed the Facade. MissionViewModel now goes through MissionApplicationService, which owns the store and the domain service.
